# WorkFlow elephc native bundle

This experimental bundle would contain the elephc-built executable, the C shared
library, the compiler-generated C header, and the Node/Python/C examples.

Unlike the [TypePHP SDK](../typephp/DISTRIBUTION.md), it is **not tied to a
matching PHP runtime image**. elephc links a small runtime into the output and
this core needs no PHP, PHPX, GMP/MPFR, or host extension library:

- `workflow-native` — reads one JSON request from stdin, prints one response.
- `libworkflow_native.{dylib,so}` — the C-ABI shared library.
- `libworkflow_native.h` — generated by the compiler; authoritative for the ABI.

What it still is **not**:

- A cross-platform binary. Each artifact targets one of elephc's supported
  targets (macOS ARM64, Linux ARM64, Linux x86_64; iOS ARM64 is library-only).
- A self-contained operating-system image. The artifact carries the Elephc
  runtime but assumes the standard system libraries of its target, so match the
  artifact to the host platform and libc family (glibc, not musl).
- A tested release. CI does not install elephc yet and no SDK archive is built
  or published; see the ADR `0007-elephc-native-module`.

Your application owns durable state, concurrency control, work delivery, and
external idempotency. The C library must be initialized, called, and closed on
the same OS thread; the ABI is single-threaded and shutdown is terminal. See the
repository's `docs/languages.md` and `mod/elephc/README.md` for the complete
contract.

WorkFlow is MIT licensed, and so is elephc, which simplifies redistribution
versus the TypePHP path: there is no embedded PHP runtime or GPL-licensed
compiler to notice in the bundle.
